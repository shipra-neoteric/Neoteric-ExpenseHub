# Deploying Neoteric ExpenseHub — GitHub + Render + Vercel

This walks through: push to GitHub → deploy the API on Render → deploy the
client on Vercel → connect the two → seed and verify. Do the steps in this
order — Render before Vercel — because Vercel needs Render's URL, and then
Render needs Vercel's URL back.

You already have a working MongoDB Atlas cluster from local setup — the same
one works for production, no new database needed.

---

## 1. Push to GitHub

1. Go to https://github.com/new (you're logged in as **shipra9505**).
2. Repository name: `neoteric-expensehub` (or whatever you like).
3. **Leave "Add a README", ".gitignore", and "license" unchecked** — this repo
   already has all of that; ticking them creates conflicting files.
4. Visibility: your choice (Private is reasonable for now).
5. Click **Create repository**. GitHub will show you a page with a URL like
   `https://github.com/shipra9505/neoteric-expensehub.git` — copy it.

Now, in a terminal at the project root (`C:\Users\khand\Desktop\Neoteric-ExpenseHub`):

```bash
git add -A
git commit -m "Initial commit: Site Expenses L1"
git branch -M main
git remote add origin https://github.com/shipra9505/neoteric-expensehub.git
git push -u origin main
```

The first push will open a browser window to authenticate with GitHub (Git
Credential Manager, already installed with Git for Windows) — sign in there
once and it's remembered.

**Sanity check**: refresh the GitHub repo page — you should see `client/`,
`server/`, `README.md`, etc. `server/.env` and `server/uploads/` should
**not** appear (they're gitignored — if `.env` shows up, stop and tell me,
don't push again until it's removed from git history).

## 2. Deploy the API to Render

### Option A — Blueprint (faster, uses the `render.yaml` already in the repo)

1. Go to https://dashboard.render.com → **New +** → **Blueprint**.
2. Connect your GitHub account if you haven't, then select the
   `neoteric-expensehub` repo. Render reads `render.yaml` at the repo root
   automatically.
3. It will show one service, **expensehub-api**, with most fields
   pre-filled. Two fields need manual values (marked `sync: false` in the
   blueprint, so Render will prompt for them):
   - `MONGO_URI` → paste your Atlas connection string (the same one from
     `server/.env` locally, with `/expensehub` before the `?`).
   - `CLIENT_ORIGIN` → leave blank for now, you'll fill this in after step 3
     (Vercel) gives you a URL.
4. Click **Apply** / **Create**. `JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET`
   are auto-generated by Render (`generateValue: true` in the blueprint) —
   you never need to see or set these yourself.
5. Wait for the first deploy to finish (Render will show build logs). Once
   live, copy the service URL — something like
   `https://expensehub-api.onrender.com`.

### Option B — Manual (if you'd rather not use the Blueprint)

1. **New +** → **Web Service** → connect the repo.
2. **Root Directory**: `server`
3. **Runtime**: Node
4. **Build Command**: `npm install`
5. **Start Command**: `npm start`
6. **Instance Type**: Free (fine for this)
7. Add environment variables (Render's Environment tab):
   | Key | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `MONGO_URI` | your Atlas connection string |
   | `JWT_ACCESS_SECRET` | any long random string (e.g. generate one at https://generate-secret.vercel.app/32) |
   | `JWT_REFRESH_SECRET` | a **different** long random string |
   | `JWT_ACCESS_EXPIRES_IN` | `15m` |
   | `JWT_REFRESH_EXPIRES_IN` | `7d` |
   | `APP_TIMEZONE` | `Asia/Kolkata` |
   | `CLIENT_ORIGIN` | leave blank for now |
   | `UPLOAD_DIR` | `uploads` |
   | `MAX_UPLOAD_MB` | `8` |
   | `LOW_BALANCE_THRESHOLD_PAISE` | `200000` |
8. Create the service and wait for it to deploy. Copy its URL.

### Confirm Atlas allows Render's traffic

Render's free tier uses dynamic outbound IPs, so **Atlas → Network Access**
must allow `0.0.0.0/0` (Allow access from anywhere). You already set this up
when connecting locally — just confirm it's still there.

### Sanity check

Visit `https://<your-render-url>/health` in a browser — it should return
`{"status":"ok"}`. If it doesn't load at all, check Render's **Logs** tab for
the actual error (usually a missing/wrong `MONGO_URI`).

---

## 3. Deploy the client to Vercel

1. Go to https://vercel.com/new, connect GitHub, select the
   `neoteric-expensehub` repo.
2. **Root Directory**: click "Edit" and set it to `client`.
3. Vercel auto-detects Vite — Build Command `npm run build`, Output
   Directory `dist` should already be filled in correctly. Leave them.
4. **Environment Variables** — add:
   | Key | Value |
   |---|---|
   | `VITE_API_BASE_URL` | `https://<your-render-url>/api` (the URL from step 2, with `/api` appended) |
5. Click **Deploy**. Wait for it to finish, then copy the resulting URL —
   something like `https://neoteric-expensehub.vercel.app`.

---

## 4. Connect Render back to Vercel

Now that you have the Vercel URL:

1. Go back to the Render dashboard → your `expensehub-api` service →
   **Environment**.
2. Set `CLIENT_ORIGIN` to your exact Vercel URL, e.g.
   `https://neoteric-expensehub.vercel.app` (no trailing slash).
3. Save — Render redeploys automatically with the new value.

This matters: without it, the API's CORS check rejects every request from
the deployed client and login will fail silently (a 401/CORS error in the
browser console, not a visible error banner) — the browser blocks the request
before it even reaches your app's error handling.

---

## 5. Seed the production database

The seed script is idempotent — safe to run once against production. Easiest
way: run it from your own machine, pointed at the same Atlas cluster Render
uses (which is already the case, since your local `server/.env` already
points at that Atlas cluster):

```bash
cd server
npm run seed
```

If you'd rather run it from Render directly: Render's free tier doesn't
include a persistent shell, but Render's dashboard has a **Shell** tab on
paid plans, or you can temporarily add a one-off Job. For a free-tier
deploy, running it from your own machine (as above) is simplest and
achieves the same result, since both point at the same database.

## Known limitation: uploaded receipts are not persistent on Render's free tier

Render's free/standard web services use an **ephemeral filesystem** — any
file saved to `server/uploads/` (receipt images/PDFs) is **lost on every
redeploy or restart**. This doesn't affect any financial data (that's all in
MongoDB), only the uploaded receipt files themselves.

For a real production deployment, before relying on receipts long-term,
either:
- Upgrade to a Render **persistent disk** (paid, mounts a durable volume), or
- Move attachment storage to object storage (S3, Cloudflare R2, or similar) —
  this would mean changing `server/src/config/upload.js` and
  `attachmentController.js` to upload to that service instead of local disk.

This is called out here rather than silently shipped, since it's the kind of
thing that looks fine in testing and then loses real data later.

## Redeploying after future code changes

Both Render and Vercel auto-deploy on every push to `main` once connected —
just `git push` and both redeploy on their own. No further manual steps
needed unless you change environment variables.
